# 演習4-2: パフォーマンス最適化 — 学び・気づきのログ

（実装・動作確認の結果をここに記録してください）

課題1では最大震度を4を設定しました。ブックスキーマの中で一番クエリの深度が深いものがブックコネクションだったんですけども、そちらは4で通過したので4を設定しています。

3を設定した場合にデプス超過時のエラーメッセージが出力されていまして、そちらに関してはクリーンのバリデーションルールというものの内容が表示されています。なので、GraphQL側がResolverを実行する前の段階でバリデーションで弾いていることが確認できています。

課題2について、まずページネーションの実装は、実装構想が大きいので今回省略して、Bookパフォーマンスリースのみで共同の確認をしています。パフォーマンスブックスについて、Max Complexityを100を設定しました。

その上でResolverのクエリごとにコンプレクシー10を設定しています。この状態でクエリを実行すると問題なく、最大より最大コンプレクシティを下回るのでクエリは完了しました。実験的にMAXを9に設定して実行したところ、クエリの複雑度調査エラーが発生することを確認することができました。

課題3について、ステップ1のハッシュ値のみの送信に関してはエラーが発生しまして、パーシスティッドクエリーノットファウンドというエラーが返ってきています。なので、ハッシュ値がそもそも登録されていないのだと思います。

ステップ2でハッシュとクエリをセットで送信してキャッシュさせた後に、ステップ3でハッシュのみを再送信したところ、問題なくクエリの結果が返ってきました。
